Smart Tourism System For Junagadh

Route • Time • Budget • Data
Problem Statement
Tourists visiting Junagadh face significant challenges in optimizing their travel itineraries due to a lack of integrated planning systems. By specifically utilizing Greedy algorithms, our engine solves the inability to mathematically maximize attractions within strict daytime and budget limits, calculates absolute shortest distances across widespread historical zones, prevents overlapping schedules, and provides offline data compression for high-altitude connectivity drops (e.g., Girnar).

1 · Shortest Path

Dijkstra's Algorithm

Purpose: Finds the minimum-distance route between a starting location and a destination when all edge weights are non-negative.

How it works
  1. Set the source distance to 0 and all other distances to infinity.
  2. Repeatedly choose the unvisited location with the smallest known distance.
  3. Relax its outgoing edges if a shorter distance is found; store each predecessor and reconstruct the route.

2 · Minimum Spanning Tree

Prim's Algorithm

Purpose: Builds a minimum spanning tree (MST) that connects every location with the lowest total edge weight and no cycles.

How it works
  1. Start with Railway Station as the tree's first vertex.
  2. Choose the lightest edge from a selected vertex to a vertex not yet in the tree.
  3. Add that edge and new vertex; repeat until all 13 locations are connected.

3 · Minimum Spanning Tree

Kruskal's Algorithm

Purpose: Connects every location with minimum total distance by selecting edges globally in ascending weight order.

How it works
  1. Sort all candidate edges from smallest to largest weight.
  2. Use disjoint sets (Union-Find) to check whether an edge joins separate components.
  3. Add only edges that do not create a cycle; stop after 12 edges connect 13 vertices.

4 · Greedy Scheduling

Activity Selection

Purpose: Chooses sightseeing activities that do not overlap, allowing the tourist to complete as many visits as possible.

How it works
  1. Track the finish time of the last selected activity.
  2. Accept the next activity only when its start time is at or after that finish time.
  3. This C implementation scans its preset list in order; it does not sort it first.

5 · Greedy Scheduling

Job Scheduling

Purpose: Assigns tour guides to limited time slots to maximize the total fee while respecting each job's deadline.

How it works
  1. Sort guide assignments by fee/profit from highest to lowest.
  2. For each assignment, search backward from its deadline for the latest free slot.
  3. Place the assignment if a valid slot is available; add its fee to total revenue.

6 · Tree Compression

Huffman Coding

Purpose: Creates variable-length, prefix-free binary codes for destination names; frequently referenced destinations can be encoded with fewer bits.

How it works
  1. Start with one leaf per destination, weighted by its illustrative frequency.
  2. Repeatedly combine the two lowest-frequency nodes into a parent whose weight is their sum.
  3. Label left/right branches 0/1; each root-to-leaf path gives a destination's code.

7 · Greedy Optimization

Fractional Knapsack

Purpose: Maximizes estimated tourist-experience rating within a time limit by allowing a fraction of the final package.

How it works
  1. Calculate each package's rating per hour and sort from highest to lowest ratio.
  2. Take each package fully if it fits in the remaining time.
  3. Otherwise take the remaining time fraction and stop when the time budget is exhausted.

Innovation & Application
  • Smart City Integration: Can be deployed by the Junagadh Municipal Corporation for dynamic traffic routing and tourism analysis.
  • Offline Mobile App: Huffman compressed textual history guides allow usage even when the cellular network drops in Girnar hills.
  • Personalized Itineraries: Algorithms automatically adapt to a tourist's changing budget limits or remaining daytime hours dynamically.
Result & Conclusion
By applying Dijkstra, Prim, Kruskal, Activity Selection, Job Scheduling, Fractional Knapsack, and Huffman Coding, this engine removes the guesswork from Junagadh tourism. It finds shortest paths, builds a minimum transport network, prevents schedule conflicts, optimizes tourist experience within time limits, and compresses guide data for constrained connectivity.
